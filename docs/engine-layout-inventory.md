## Discovery and audit guidance

Start at `Cargo.toml`, enumerate workspace members and each package's explicit or conventional targets, then follow the target into source. Do not assume an engine has a root `src/`: TokenZero and GraphZero are virtual workspaces, while FSZero combines a root package with wrapper crates. Audit both explicit `[[bin]]` targets and conventional `src/main.rs` / `src/bin/*.rs`, then trace re-exports and command-mode dispatch before declaring an entry `not present`. A `not present` result above means no matching dependency or distinct binary target was found in the current manifests and source tree.

## Drift summary

- Layouts are intentionally asymmetric: FSZero owns its core at the repository root; TokenZero and GraphZero place implementations under `crates/`.
- CAS names have converged only partly: TokenZero and GraphZero use `SharedCas`; FSZero uses `CasStore`. Each still owns an engine-local implementation and resolver.
- Raw-worker packaging differs: GraphZero has a dedicated binary; FSZero and TokenZero expose raw-worker modes through existing surface binaries.
- All three consume `zero-abi` and `zero-ref` in selected packages. None currently declares `zero-store`.
- CodeMode and MCP remain separate deployment entries; deployments choose exactly one and never run both simultaneously.
