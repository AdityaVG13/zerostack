# Persisted Format Change Checklist

Use this checklist for any pull request that changes bytes or JSON persisted by the store, pack, or semantic subsystems. The concrete persistence surfaces and their current compatibility keys are inventoried below; the linked definitions are the source of truth.

## Persisted format inventory

| Subsystem | Persisted format | Current version anchor and reader behavior |
| --- | --- | --- |
| Store | Snapshot shard (`GZSH`) | `FORMAT_VERSION` and `FORMAT_VERSION` feed `ShardHeader.version`; `ShardHeader::parse` accepts exactly those versions ([`format.rs:18-22`](../../crates/graphzero-store/src/store/format.rs#L18-L22), [`format.rs:34-52`](../../crates/graphzero-store/src/store/format.rs#L34-L52), [`format.rs:66-82`](../../crates/graphzero-store/src/store/format.rs#L66-L82)). |
| Store | Snapshot manifest (`GZMF`) | Byte 4 is governed by `MANIFEST_VERSION`; `validate_manifest_version` rejects legacy, future, and otherwise unsupported values ([`manifest.rs:1-6`](../../crates/graphzero-store/src/store/manifest.rs#L1-L6), [`manifest.rs:21`](../../crates/graphzero-store/src/store/manifest.rs#L21), [`manifest.rs:75-82`](../../crates/graphzero-store/src/store/manifest.rs#L75-L82), [`manifest.rs:142-160`](../../crates/graphzero-store/src/store/manifest.rs#L142-L160)). |
| Store | WAL delta segment (`GZDL`) | The version field is byte `0x04`, currently the literal `0x01` written by `DeltaLog::commit` and checked by `parse_segment_header`; there is no separate version constant ([`delta_log.rs:4-15`](../../crates/graphzero-store/src/store/delta_log.rs#L4-L15), [`delta_log.rs:168-190`](../../crates/graphzero-store/src/store/delta_log.rs#L168-L190), [`delta_log.rs:207-216`](../../crates/graphzero-store/src/store/delta_log.rs#L207-L216)). |
| Store indexer | Extraction records sidecars (`records_latest.jsonl` and legacy `records_latest.json`) | `RecordsSidecar.version` and `RecordsSidecarLogEntry.version` are governed by `RECORDS_SIDECAR_VERSION`; unknown JSONL versions are skipped and a mismatched legacy JSON version is ignored ([`indexer.rs:46-54`](../../crates/graphzero-store/src/store/indexer.rs#L46-L54), [`indexer.rs:89-110`](../../crates/graphzero-store/src/store/indexer.rs#L89-L110), [`indexer.rs:113-141`](../../crates/graphzero-store/src/store/indexer.rs#L113-L141)). |
| Store indexer | Name-bigram sidecar (`name_bigram_*.bin`, GZNB) | `NAME_BIGRAM_VERSION` / magic `GZNB`; `NameBigramIndex::from_bytes` rejects other versions; missing file is silent fallback to build ([`name_bigram.rs`](../../crates/graphzero-store/src/store/query/name_bigram.rs)). |
| Pack | Signed `manifest.json` and its shard/semantic artifact inventory | `PackManifest.schema_version` is governed by `MANIFEST_SCHEMA_VERSION`; `PackManifest::read_json` rejects any other schema. `PackShardEntry` and `PackSemanticSidecarEntry` identify the persisted artifacts covered by that manifest ([`graphzero-pack/src/manifest.rs:10-26`](../../crates/graphzero-pack/src/manifest.rs#L10-L26), [`graphzero-pack/src/manifest.rs:35-47`](../../crates/graphzero-pack/src/manifest.rs#L35-L47), [`graphzero-pack/src/manifest.rs:102-114`](../../crates/graphzero-pack/src/manifest.rs#L102-L114)). Pack `.gzsh` artifacts retain the store shard version above, and semantic sidecars retain the semantic shard version below; artifact verification opens each shard through `ShardReader` ([`build.rs:213-229`](../../crates/graphzero-pack/src/build.rs#L213-L229)). |
| Pack | Installed registry (`.graphzero/packs/registry.json`) | `PackRegistry::load` and `PackRegistry::save` serialize the top-level `packs` array without a schema-version field. `InstalledPackRecord.version` is the installed pack's release version, not the registry schema ([`pack_registry.rs:9-25`](../../crates/graphzero-store/src/store/pack_registry.rs#L9-L25), [`pack_registry.rs:32-50`](../../crates/graphzero-store/src/store/pack_registry.rs#L32-L50)). A registry-shape change is therefore blocked by item 1 below until the format has an explicit schema-version field to bump. |
| Semantic | Mmap-friendly `GZSV` shard/pack sidecar | `SemanticHeader.version` is governed by `SEMANTIC_VERSION` (current v2) with `SEMANTIC_V1_VERSION` retained for read-back. `read_header` rejects every other version; v2 requires an appended SHA-256 body digest, while v1 opens only as `SemanticIntegrity::LegacyUnverified` ([`graphzero-semantic/src/shard.rs`](../../crates/graphzero-semantic/src/shard.rs)). Pack installation copies these files from `PackManifest.semantic_sidecars`, and installed reads use `SemanticShardReader::open` ([`semantic_index.rs:87-117`](../../crates/graphzero-pack/src/semantic_index.rs#L87-L117)). |

The semantic model-pin JSON is also persisted, but its `SemanticManifest` currently has no format-version field; it contains `model_artifact_sha256` and `dimension` only ([`graphzero-semantic/src/manifest.rs:7-29`](../../crates/graphzero-semantic/src/manifest.rs#L7-L29)). A shape change to that JSON is blocked by item 1 until an explicit schema-version field exists.

## Required PR checklist

A format-changing PR is not release-ready until all four boxes are satisfied for every affected row in the inventory.

- [ ] **1. Bump the persisted format version explicitly.** Update the exact governing key: store shards use `FORMAT_VERSION` / `ShardHeader.version` ([`format.rs:21-22`](../../crates/graphzero-store/src/store/format.rs#L21-L22), [`format.rs:36-42`](../../crates/graphzero-store/src/store/format.rs#L36-L42)); snapshot manifests use `MANIFEST_VERSION` at byte 4 ([`manifest.rs:21`](../../crates/graphzero-store/src/store/manifest.rs#L21), [`manifest.rs:142-160`](../../crates/graphzero-store/src/store/manifest.rs#L142-L160)); WAL segments use the version byte at `0x04` written and checked in `delta_log.rs` ([`delta_log.rs:183-186`](../../crates/graphzero-store/src/store/delta_log.rs#L183-L186), [`delta_log.rs:207-216`](../../crates/graphzero-store/src/store/delta_log.rs#L207-L216)); records and history use `RECORDS_SIDECAR_VERSION` / their `version` fields and `GRAPH_HISTORY_VERSION` / `GraphHistoryEntry.version` ([`indexer.rs:54,89-103`](../../crates/graphzero-store/src/store/indexer.rs#L54), [`indexer.rs:209-214`](../../crates/graphzero-store/src/store/indexer.rs#L209-L214)); pack manifests use `MANIFEST_SCHEMA_VERSION` / `PackManifest.schema_version` ([`graphzero-pack/src/manifest.rs:10`](../../crates/graphzero-pack/src/manifest.rs#L10), [`graphzero-pack/src/manifest.rs:35-47`](../../crates/graphzero-pack/src/manifest.rs#L35-L47)); semantic mmap shards use `SEMANTIC_VERSION` / `SemanticHeader.version`, retaining `SEMANTIC_V1_VERSION` only for legacy read-back ([`graphzero-semantic/src/shard.rs`](../../crates/graphzero-semantic/src/shard.rs)). An unversioned persisted JSON shape, including `PackRegistry` or `SemanticManifest`, must gain an explicit schema-version field in the same PR before its shape changes ([`pack_registry.rs:19-22`](../../crates/graphzero-store/src/store/pack_registry.rs#L19-L22), [`graphzero-semantic/src/manifest.rs:7-11`](../../crates/graphzero-semantic/src/manifest.rs#L7-L11)).

- [ ] **2. Prove old artifacts still read back.** Commit or construct an artifact encoded exactly as the previous version, then exercise the current public/opening reader and assert its observable records, spans, hashes, or entries—not only that parsing returns `Ok`. The existing shard migration is the precedent: `SpanEntry` preserves the v1 wire row and `SpanEntry::from` upgrades it to the current `SpanEntry` ([`format.rs:122-149`](../../crates/graphzero-store/src/store/format.rs#L122-L149), [`format.rs:157-168`](../../crates/graphzero-store/src/store/format.rs#L157-L168)); the hot-path reader selects the v1 or current span width from the header version ([`hot_path.rs:8-30`](../../crates/graphzero-store/src/store/hot_path.rs#L8-L30)). The same test must cover each changed reader: `Manifest::decode`, `read_segment`, `load_records_sidecar` / graph-history readers, `PackManifest::read_json` plus artifact opening, or `SemanticShardReader::open`, as applicable ([`manifest.rs:151-175`](../../crates/graphzero-store/src/store/manifest.rs#L151-L175), [`delta_log.rs:256-264`](../../crates/graphzero-store/src/store/delta_log.rs#L256-L264), [`indexer.rs:113-141`](../../crates/graphzero-store/src/store/indexer.rs#L113-L141), [`graphzero-pack/src/manifest.rs:102-114`](../../crates/graphzero-pack/src/manifest.rs#L102-L114), [`graphzero-semantic/src/shard.rs:93-110`](../../crates/graphzero-semantic/src/shard.rs#L93-L110)).

- [ ] **3. State rollback behavior for an older binary reading the new artifact.** The PR description must choose **deny with a diagnostic** or **silent skip/fallback**, identify the exact reader, and state whether retained old artifacts are needed for rollback. Current deny examples are `ShardHeader::parse`, `validate_manifest_version`, `parse_segment_header`, `PackManifest::read_json`, and semantic `read_header` ([`format.rs:66-82`](../../crates/graphzero-store/src/store/format.rs#L66-L82), [`manifest.rs:75-82`](../../crates/graphzero-store/src/store/manifest.rs#L75-L82), [`delta_log.rs:207-216`](../../crates/graphzero-store/src/store/delta_log.rs#L207-L216), [`graphzero-pack/src/manifest.rs:102-114`](../../crates/graphzero-pack/src/manifest.rs#L102-L114), [`graphzero-semantic/src/shard.rs:93-110`](../../crates/graphzero-semantic/src/shard.rs#L93-L110)). Current silent-skip/fallback examples are records-sidecar unknown-version skipping and graph-history version filtering ([`indexer.rs:113-141`](../../crates/graphzero-store/src/store/indexer.rs#L113-L141), [`indexer.rs:231-237`](../../crates/graphzero-store/src/store/indexer.rs#L231-L237), [`indexer.rs:256-267`](../../crates/graphzero-store/src/store/indexer.rs#L256-L267)).

- [ ] **4. Add a release-note entry.** Record the affected format, old and new version values, migration/read-back guarantee, and the chosen rollback behavior in `CHANGELOG.md`, whose entries follow the repository release-note convention ([`CHANGELOG.md:1-7`](../../CHANGELOG.md#L1-L7)).

## Reviewer evidence

The PR description should list the affected inventory rows, link the version bump, name the old-artifact read-back test, quote the rollback note, and link the `CHANGELOG.md` entry. Those four evidence items correspond directly to the required version anchors, compatibility precedent, reader behaviors, and release-note location above.
