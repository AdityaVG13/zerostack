# Authority, Corrections, and Supersession Rules

**Author:** Aditya G  
**Version:** Draft 6

This file prevents a model from implementing a historical statement that was later corrected or re-scoped.

## Authority order

1. Draft 6 canonical specifications and correction entries.
2. Draft 5 detailed theorem and implementation material.
3. Draft 4 and Draft 3 auxiliary results that are not contradicted by Draft 5 or Draft 6.
4. Draft 2, Draft 1, and earlier waves as historical lineage.

An older claim remains usable when it is listed as `retained`, `strengthened`, `renamed`, or `supplementary` in the lineage table. It is not current authority when listed as `superseded`, `corrected`, `deprecated architecture`, or `empirical only`.

## Principal corrections

### A. Model integration was overemphasized in early waves

Current architecture: ZeroStack is a harness-side backend. Direct KV, tokenizer, or hidden-state installation is optional and outside the foundation. Model-agnostic means any model exposed through a tool-capable harness can use the same backend through an adapter.

### B. One token means control-plane compression, not information erasure

Current primary target: one logical `Zero Execute` call, or one/two compact model-visible decision exchanges. Literal token counts are a measured coordinate. Request bytes, exact project state, reasoning, backend work, output materialization, and verification remain charged.

### C. Retrospective rewrite theorem

The broad Draft 4 statement is superseded by the Draft 5 exact longest-common-prefix characterization. A rewrite does not necessarily destroy every later token if the rewritten request remains an exact prefix of the prior residual. Current cache economics must use the exact common-prefix length.

### D. Q99 is coordinate-specific

`Provider prompt-cache hit`, `L2 logical causal reuse`, `L3 physical residency`, `model-visible context elimination`, and `complete-work reduction` are separate quantities. No single percentage may substitute for all of them.

### E. Never break the cache is scoped

ZeroStack can guarantee that its stable append-only interaction path does not retrospectively rewrite its own prior capsules. It cannot guarantee provider residency, prevent genuine project invalidation, or call stale state a hit.

### F. No degradation is scope-bound and operational

No degradation requires same model, same harness, same reasoning allowance, baseline strategy inclusion, exact fallback reserve, a sound protected verifier or human authority, and future-safe successor publication. Unsupported semantic dimensions remain `Unknown`.

### G. Approximate state

Low reconstruction error alone does not authorize use. Approximate state is protected-exact only when its full uncertainty envelope is certified inside one protected decision cell, or an exact authority verifies the result.

### H. Learning and capabilities

A successful episode is not automatically reusable authority. It may propose a capability asset. Execution requires rooted scope, preconditions, dependencies, verifier, freshness, rollback, and revocation.

## Current interpretation of core names

- **RACC:** Recovery-Aware Context Compression, the umbrella program.
- **RACC-R:** protected recovery/replay and receipt-backed nonregression layer.
- **Zero Execute:** harness-visible programmatic tool operation that invokes the backend.
- **Q99:** >=99% reuse or reduction in a precisely named coordinate and measurement window.
- **Causal cache:** exact or receipt-valid derived project state keyed by constructor, contract, dependencies, and payload formation.
- **Decision view:** model-visible evidence sufficient for the next protected semantic decision, with exact expansion authority.

## Explicit non-claims

Draft 6 does not claim:

- universal one-call completion for arbitrary tasks;
- universal 99% complete-work reduction;
- literal deletion of fresh information;
- identical hidden reasoning traces through black-box APIs;
- historical novelty of every constituent theorem;
- graph completeness without a certificate;
- semantic superiority outside verifier or human scope;
- provider cache permanence;
- zero storage, indexing, verification, or maintenance cost.
