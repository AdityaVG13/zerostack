# Bake-off: FSZero vs fff vs rg vs grep vs code-RAG (fszero-4d2)

Generated by `benchmarks/bakeoff.py` -- do not hand-edit numbers.
Hardware: Apple M5 Max / 48 GB. Benchmark commit: `308ef8da2db5` (dirty=false). Date: 2026-07-10T08:13:47Z.

Corpora: deterministic synthetic rust-like trees (`gen_corpus.py`, seed 42). 20 seeded questions per corpus (8 'which file defines fn X', 4 'which file calls X', 8 'find the string L'), derived from corpus structure, never hand-tuned. Correct iff the tool's agent-visible output contains the ground-truth relative path. Tokens per answer = bytes / 4 (stated proxy; no tokenizer invoked). Every question runs once per tool -- no retries, no dropped cases.

Tool surfaces: fszero via its real MCP stdio surface (bytes = raw JSON-RPC response line), measured both as a warm long-lived server and as a fresh process per query; rg/grep spawn per query (their normal model); fff via its official Python SDK in-process (no CLI exists); bm25-rag returns its top-5 40-line chunks as injected context.

**Measurement order (fszero-hyht):** runner default is `--order-policy shuffle` (seeded pure-scan permutations before fszero cold index). Multi-matrix aggregation publishes the conservative (max) median wall. Prefer `--order-shuffles >= 3` or `--order-policy dual` before publishing competitor medians. Optional `FSZERO_BAKEOFF_PURGE=1` between pure tools. **Historical numbers below** were produced under the pre-hyht fixed order (rg→grep→fff→bm25-rag→fszero); treat competitor wall-time rank as potentially page-cache-biased until regenerated.

**Latency labeling (fszero-67pr):** per-tool "median ms" is a **single-shot cross-question mix** (one wall time per question, then median across the 20 heterogeneous questions). It is **not** a trial-median of a repeated op; p95 of n=1 is undefined. Do not use these as absolute latency gates. Accuracy remains single-shot by design.

## Exclusions

- **smfs (supermemoryai/smfs)**: Requires a Supermemory cloud account and API key (`smfs login`); the filesystem syncs bidirectionally with Supermemory's remote servers and has no documented offline/local-only mode (verified 2026-07-10 from github.com/supermemoryai/smfs). Infeasible without an account -- excluded.
- **embedding-based code-RAG**: No embedding model runtime already installed; a real pipeline needs a multi-hundred-MB model download plus per-chunk inference. Replaced by the documented simpler bm25-rag baseline (rank-bm25 over 40-line chunks); note a real embedding pipeline's index build cost is strictly HIGHER than bm25's.
- **fff one-shot CLI**: fff ships no standalone CLI by design (README: 'FFF is a file search library, not a CLI'); measured instead through its official Python SDK in-process (fff-search 0.9.6), its intended long-lived mode.
